Budget Tracker

A personal expense tracker that grew from a small database-connection experiment into a full-stack application. I built it one verified layer at a time, and documented the systems problems that had to be solved before the first feature could ship.

View source repository →

What it does

  • Records expenses with a description and amount, displayed in Naira (₦), and shows the running total.
  • Adds and deletes expenses without reloading the page; the displayed total previews an amount while it is being typed.
  • Produces a separate spending summary, CSV export, and monthly chart from the same MySQL data.

The app uses Go's net/http, database/sql, and html/template, with MySQL 8, Tailwind CSS, and vanilla JavaScript. The reporting companion uses Python, pandas, matplotlib, and mysql-connector-python. I intentionally used neither a frontend framework nor an ORM so I could work directly with HTTP, SQL, and DOM updates.

The build, step by step

  1. Prove Go can reach MySQL. Started with a tiny Go program that only connected and printed a confirmation, before introducing application logic.
  2. Debug the local database installation. The initial install left mysql-common removed but not purged, and no mysql.service for systemd. After reinstalling, root authentication failed because MySQL 8.4 no longer enabled mysql_native_password by default, so setup moved to caching_sha2_password. A recovery-mode mysqld process also resisted termination; dmesg revealed AppArmor denying the signal. The eventual fix was a clean purge and reinitialization with mysqld --initialize-insecure, followed by a carefully verified password reset.
  3. Verify real database operations. Once the server was stable, inserted an expense and read it back from the command line, keeping database checks separate from HTTP.
  4. Build the HTTP layer incrementally. Added a standard-library Go server, first rendering the expense list, then adding form submission and database inserts route by route.
  5. Shape the interface for its use. Added responsive Tailwind styling, a muted emerald finance palette, and Naira currency formatting.
  6. Add browser interactions in verified stages. Implemented client-side checks, fetch-based submission with separate full-page and partial-HTML responses, a live total preview, and no-reload deletion.
  7. Read the same data from Python. Kept reporting as an independent script that prints summary statistics and exports CSV and a monthly spending chart, demonstrating that the data is usable outside the Go app.

What I learned and what is next

The longest debugging stretch came before application code: tracing package state, MySQL authentication changes, systemd behavior, and an AppArmor policy taught me to verify each system layer instead of assuming a failed connection was a Go bug. The project is still intentionally in progress: credentials remain hardcoded, automated tests and stronger server-side validation are needed, and categories, date filters, and a compiled Tailwind build are planned rather than shipped.
